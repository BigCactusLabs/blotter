# Codex review of the v2 plan (2026-09-01)

Reviewer: gpt-5.6-sol, reasoning high, read-only over the tree at ac6f642. Dispositions are recorded in §9 of `docs/plans/2026-09-01-blotter-v2-plan.md`.

## Critical

1. **Contract 6 is assigned before contract 6 is complete.** Phase 2 bumps `meta.contract` to 6, while Phases 3–5 later change record shapes, commands, and envelopes (`docs/plans/2026-09-01-blotter-v2-plan.md:81-115`). The implementation has one public contract constant (`src/output.rs:6`), whose purpose is skew detection (`docs/plans/2026-07-09-papercuts-design.md:84-86`). Consumers would see several incompatible protocols all labeled 6. A concrete gap: Phase 3 introduces `accepted`/`invalid`, but Phase 5 changes `verify`; until then, current logic anchors every non-dropped resolved cut (`src/commands/verify.rs:63-76`). Use stacked review branches with one atomic merge for Phases 2–5, or assign distinct intermediate contracts.

2. **The v1 refusal is not specified at the boundary that prevents writes.** A known record missing a new required field currently becomes `ScanIssue::Malformed` (`src/store.rs:778-803`); append dedupe silently skips scan errors and continues to append (`src/store.rs:637-660`), including tear-healing a newline (`src/store.rs:685-717`). `doctor` marks malformed lines fixable (`src/commands/doctor.rs:414-452`), so `doctor --fix` could quarantine an entire v1 ledger. `archive` can fold and copy-swap a mixed file (`src/commands/archive.rs:149-225`). `sweep` converts every per-log error into an exit-0 skip (`src/commands/sweep.rs:92-120`). Phase 3 only says “scanner rejects” and ambiguously asks `doctor.rs` to report the line (`docs/plans/2026-09-01-blotter-v2-plan.md:94-99`). r48 must require a pre-fold, in-lock version probe that:

   - returns one named non-retryable exit-65 error on stderr;
   - appends or rewrites no byte, including no tear-heal;
   - makes `doctor --fix` and `archive` create no sidecars;
   - defines whether one v1 input aborts all of `sweep` or is an explicit sweep exception;
   - defines empty logs, unknown kinds, malformed lines, `v != 2`, and mixed-file precedence.

## High

3. **Record identity remains underspecified.** Existing cut identity is an exact framed sequence beginning `bl1`, with sorted-unique tags and a fixed digest width (`src/lib.rs:350-400`; design r10 at `docs/plans/2026-07-09-papercuts-design.md:266-270`). The plan says only that cut identity “hashes impact” and that promotion hashes several fields (`docs/plans/2026-09-01-blotter-v2-plan.md:52,94`). r48 must state exact version/domain literals, field order, framing, digest width, source sorting/deduplication, stored canonical form, and whether `v` and `origin` participate—for cuts, dogears, and promotions. It must also decide whether dogears continue hashing `bl1` (`src/lib.rs:374-385`) in a `v:2` ledger.

4. **Promotion does not fit the current fold/list contract, and the plan does not define the replacement.** `ListItem` requires text, tags, cwd, status, and optional resolution (`src/lib.rs:128-146`), while the proposed promotion has none of those lifecycle fields. `list` applies status/tag filters and renders only severity groups and dogears (`src/commands/list.rs:79-101,104-136`). Also, `ListKind` is shared by `list` and `sweep` (`src/cli.rs:140-147,261-284`), so adding `Promotion` makes `sweep --kind promotion` public unless the enums split. Phase 4 only says list shows promotions (`docs/plans/2026-09-01-blotter-v2-plan.md:101-106`). r48 must define the output union, status/filter behavior, JSON and Markdown rendering, deterministic ordering, and sweep scope.

5. **`archive` can destroy promotion provenance.** A promoted source cut can later be resolved and archived because archive removes old closed `bl_` groups (`src/commands/archive.rs:149-187`). The promotion remains, leaving `sources[]` dangling even though provenance is its reason to exist (`docs/plans/2026-09-01-blotter-v2-plan.md:101-105`; checkpoint `:845-847`). r48 must say whether promotions pin their source cuts, archive with them as one closure, or may deliberately retain dangling references. `doctor` reference validation must match that choice. Section 7 lists no such risk.

6. **Removing the retired hook receiver reintroduces the host-session failure r32 prevented.** Phase 2 deletes the entire hook command (`docs/plans/2026-09-01-blotter-v2-plan.md:81-87`), but r32 keeps `hook exec claude-code` specifically so installed hooks always exit 0 (`docs/plans/2026-07-09-papercuts-design.md:467-471`); `main` bypasses clock and normal dispatch for it (`src/main.rs:22-24`). After upgrade, an installed hook gets clap exit 2 plus stderr. Either retain the no-op receiver, or make r48 explicitly supersede fail-open compatibility and add a mandatory upgrade/removal step. Section 7 omits this failure scenario.

7. **Phase 1 and Phase 2 cannot safely run in parallel as written.** Phase 1 edits `AGENTS.md`, `src/cli.rs`, and the monolithic schema value in `src/commands/schema.rs`; Phase 2 must edit those same files (`docs/plans/2026-09-01-blotter-v2-plan.md:73-87`). Phase 2 also needs README removal of the live auto/hook documentation (`README.md:91,204-212`), another Phase 1 file. Sequence Phase 1 before Phase 2 or give one phase ownership of the shared files.

8. **New promotion fields omit the existing authored-text redaction rule.** r34 requires every authored free-text field to be redacted before append (`docs/plans/2026-07-09-papercuts-design.md:487-499`). Phase 4 says nothing about `artifact.ref` or `note`. An absolute artifact path such as `/Users/alice/...` would make blotter’s own write fail `doctor --leaks`; inconsistent redact-before-hash ordering would also make doctor recomputation disagree. r48 must state validation, bounds, redaction, and identity ordering for both fields.

## Medium

9. **Disposition amendment and digest semantics are incomplete.** Phase 3 says an amend “may change” disposition (`docs/plans/2026-09-01-blotter-v2-plan.md:96`), but the fold materializes the winning amend as a replacement resolution (`src/store.rs:971-1005`). r48 must state whether disposition is required on every cut amend or inherited when omitted, and how `--promotion` is retained or cleared. It must also reject mixed cut/dogear batches atomically. Separately, “accepted in the period” does not say whether digest counts the cut timestamp, base resolution timestamp, or winning amend timestamp (`docs/plans/2026-09-01-blotter-v2-plan.md:60,114`); current digest only walks open items and windows on cut time (`src/commands/digest.rs:88-124`).

10. **The Phase 2 deletion list misses required references.** Removing hook requires `src/main.rs:22-24`, `src/commands/mod.rs:7,16,43,55-65`, hook types and dispatch in `src/cli.rs:35-62,325-349`, schema/env entries, and the no-op assertion in `tests/cli/contract.rs:1007-1020`. Removing `--include-auto` also requires the stale resolve guidance in `src/commands/resolve.rs:215-250` and its exact assertion in `tests/cli/resolve.rs:715-738`. Removing `IdNamespace` in Phase 3 requires `src/commands/archive.rs:1-5,153-166`, which the phase does not name.

11. **Deleting `tests/cli/legacy.rs` wholesale drops coverage needed by `origin`.** The module contains the current provenance round-trip and propagation tests for list, triage, digest, and verify (`tests/cli/legacy.rs:41-160`), not only `pc_` compatibility. The plan’s claim that replacing `source` costs nothing on the read side is false: source is materialized into list items and analysis outputs (`src/lib.rs:128-179`; `src/commands/triage.rs:26,910`; `src/commands/verify.rs:21-26,237-246`). Port these cases to structured-origin tests and define which derived envelopes carry `origin`.

The OTLP golden still publishes version 0.15.0 and severity attributes (`tests/fixtures/export-otlp-json-golden.jsonl:1`). Phase 6 also omits the root package version in `Cargo.lock:47-50`.

13. **Two proposed retrospect pattern types have no emission rule.** Phase 5 lists four patterns but maps all existing heuristics only to `recurrent_friction` or `failed_intervention` (`docs/plans/2026-09-01-blotter-v2-plan.md:112-114`). `documentation_gap` and `repeated_recovery` are therefore dead vocabulary. Current deterministic evidence distinguishes docs-tagged clusters and recurrence groups (`src/commands/retrospect.rs:125-164,214-277`). Define deterministic mappings or remove the unused types; the checkpoint called them “potential,” not mandatory (`docs/archive/blotter-v2-signal-floor-checkpoint-2026-09-01.md:555-590`).
